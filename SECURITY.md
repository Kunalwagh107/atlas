# Security review

**Scope:** Atlas 1.0.0, a static, browser-only mind-map workspace.
**Reviewed:** 17 November 2026 · Node 22.22.2 · npm 10.
**Method:** dependency audit, secret and sink scanning, CSP/header review, threat modelling of the
untrusted-input paths (import and images), and inspection of the existing security tests.

## Summary

Atlas has no backend, no accounts, no cookies and no environment variables, which removes most of the
usual attack surface. The remaining risks are client-side: untrusted documents and images the user
opens, supply-chain issues in the toolchain, and repo hygiene.

## SEC-01: Toolchain advisories in the Vitest chain

**Severity:** High for developer machines, none for deployed users. `vitest` is a `devDependency` and
is never bundled into `dist/`.

`npm audit` reports three advisories:

```
vitest        critical  Path traversal / arbitrary file read via @vitest/mocker redirect mock
tinypool      critical  Prototype pollution gadget in worker options → RCE
@vitest/mocker moderate Path traversal via redirect mock
```

Installed versions: `vitest@3.2.7` → `tinypool@1.1.1`, `@vitest/mocker@3.2.7`.
Patched lines are `tinypool@2.2.0` and `@vitest/mocker@5.1.0`, which only ship with `vitest@5.x`.

**Why it matters:** the RCE and file-read paths require a malicious test file, config or mock to be
executed locally. They cannot be triggered by a visitor of the deployed site, and the production
bundle is unaffected.

**Remediation (not applied, because this is a breaking major upgrade):**

```bash
npm install -D vitest@^5.1.0
npm test                 # re-verify all 145 tests
npm audit                # expect 0 vulnerabilities
```

`vitest.config.ts` is minimal (`environment: 'node'`, one setup file), so the upgrade surface is small,
but it should land as its own pull request with the full gate green. Until then, run the suite only
against trusted code, and prefer CI (which runs `npm ci` from the lockfile) over ad-hoc installs.

## SEC-02: Committed emulator state and agent notes (fixed)

`.wrangler/` (miniflare SQLite databases, temp bundles, ~550 KB of binary state) and
`.workbuddy-ai/` (local agent notes) were tracked in git despite being listed in `.gitignore`,
because `.gitignore` only affects untracked files.

**Risk:** publishing local tool state, absolute paths and internal notes with the repository; binary
churn in every diff.

**Fixed:** both paths were untracked (`git rm --cached`) and `.gitignore` was rewritten to cover
`.wrangler/`, `.workbuddy-ai/`, `brag-output/`, test output, editor/OS noise and local secret files
(`.env*`, `.dev.vars*`, `*.pem`, `*.key`). The files remain on disk; only the index changed. Two stray
root assets (`atlas-frame.png`, `atlas-presentation.gif`) were removed; their replacements are
generated by `npm run screenshots`.

**Verify:**

```bash
git ls-files | grep -E '^(dist|node_modules|\.wrangler|\.workbuddy-ai)/'   # expect no output
```

## SEC-03: `style-src 'unsafe-inline'` (accepted)

```
Content-Security-Policy: default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; …
```

React applies inline `style` attributes for per-node geometry and colour, which requires
`'unsafe-inline'` for styles. `script-src` remains `'self'` with no `'unsafe-inline'` and no
`'unsafe-eval'`, so the classic CSS-injection-to-script escalation is closed: no inline script can run,
and `base-uri 'self'` plus `object-src 'none'` block base-tag and plugin abuse.

**Residual risk:** low. CSS injection could exfiltrate data only through a `url()` fetch, and
`img-src`/`font-src` do not permit arbitrary remote origins.

## SEC-04: Broad `ws:` / `wss:` in `connect-src` (accepted for dev)

`connect-src 'self' ws: wss:` exists so the Vite dev server's HMR socket works under the CSP meta tag in
`index.html`. In production no WebSocket is opened.

**Recommendation for a hardened deployment:** override `public/_headers` in the Pages project with
`connect-src 'self'` only. Keep the meta tag as-is for local development, or gate it on
`import.meta.env.DEV`.

## SEC-05: GitHub Actions pinning (recommendation)

`.github/workflows/ci.yml` uses `actions/checkout@v4` and `actions/setup-node@v4`. Major tags are
mutable. For a hardened supply chain, pin to a commit SHA with the version in a trailing comment and
enable Dependabot for `github-actions`.

## SEC-06: Policy files (recommendation)

There is no `LICENSE` and no security contact. Add a license before accepting contributions, and a
`SECURITY.md` contact address once the repository is public.

## SEC-07: Runtime dependencies (pass)

```
gifenc@1.0.3   lucide-react@0.468.0   react@19.1.10   react-dom@19.1.10   (+ scheduler)
```

`npm audit --omit=dev` → **found 0 vulnerabilities**. Four direct runtime dependencies, no transitive

`lucide-react` supplies icons as tree-shaken components.

## SEC-08: Secrets and environment variables (pass)

- No `.env`, `.dev.vars`, key or certificate files exist in the working tree or in git history.
- `src/` contains no credentials: a scan for `api_key`, `secret`, `token`, `password`, `Bearer`,
  `AKIA…`, `ghp_…` and `sk-…` returns only design-token identifiers and bundled brand SVGs.
- The app reads **no** environment variables at build time or runtime, and the Pages project needs no
  secrets or bindings. `.gitignore` now blocks `.env*` and `.dev.vars*` pre-emptively.

## SEC-09: DOM injection sinks (pass)

No `dangerouslySetInnerHTML`, `innerHTML`, `eval`, `new Function` or `document.write` anywhere in
`src/`. All node titles, notes, tags and labels render as React text nodes and are escaped by default.
Markdown notes are rendered as structured React elements, not as HTML strings.

## SEC-10: Untrusted input paths (pass)

Two paths accept attacker-controlled data: imported files and images.

| Control | Implementation |
| --- | --- |
| Schema validation | `parseDocument` normalises every imported document against `core/mindmap/validation.ts`; unknown fields are dropped, lengths are capped, and a v1 document is migrated. |
| Colour injection | `safeColor()` whitelists hex and `rgb()/rgba()` only; `url(javascript:…)` and attribute-breaking payloads fall back to a default. |
| Prototype pollution | `__proto__` / `constructor` ids are rejected, so an import cannot write to `Object.prototype`. |
| Images | Local files only. `isSafeImageSrc` accepts `data:` and `atlas-blob:` references (never `http(s):` or relative URLs), and the CSP restricts `img-src` to `'self' data: blob:`. |
| Export markup | Titles, labels and colours are escaped or whitelisted before being written into SVG. |

These are covered by `src/export/security.test.ts`, which asserts that a `<script>` payload in a node
colour or title never reaches the exported markup.

## SEC-11: Service worker and caching (pass)

`sw.js` is generated per build with that build's hashed asset names. It precaches same-origin shell
files only, deletes older `atlas-shell-*` caches on activation, and never caches IndexedDB records,
maps or images. Navigation is network-first with an offline shell fallback, so a stale worker cannot
serve a mismatched asset set.

## Deployment headers in effect

From `public/_headers`:

```
X-Content-Type-Options: nosniff
Referrer-Policy: strict-origin-when-cross-origin
Content-Security-Policy: default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline';
  img-src 'self' data: blob:; font-src 'self' data:; connect-src 'self' ws: wss:;
  worker-src 'self'; manifest-src 'self'; object-src 'none'; base-uri 'self';
  frame-ancestors 'none'
/sw.js   → no-cache, no-store, must-revalidate
/assets/* → public, max-age=31536000, immutable
/         → no-cache
```

`frame-ancestors 'none'` prevents clickjacking; `nosniff` prevents MIME confusion; immutable hashed
assets are safe because every build changes the file name.

## Reporting a vulnerability

Open a private security advisory on the repository (or email the maintainer) rather than a public
issue. Include reproduction steps, the affected version and the browser used. Expect an initial
response within a few days; this is a volunteer-maintained project.
